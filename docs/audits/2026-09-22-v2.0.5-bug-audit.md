# 秒选 v2.0.5 Bug 审查

日期：2026-09-22  
范围：macOS 安装包、空状态主界面、任务历史、授权/试用/支付、在线更新、导入统计、任务命名、自动化测试与发布元数据。  
结论：核心筛选单元测试通过，但当前安装包仍有发布阻断项，不建议直接发给正式用户。

## 验证结果

- `mvp_tests`：94 项全部通过。
- 授权服务本地核心流程：通过（订单、签名授权、设备替换、1 天试用、微信证书防护）。
- Python 编译检查：通过。
- 当前桌面版本常量：`2.0.5`。
- 当前 `.app`：约 1.0 GB，arm64，临时 ad-hoc 签名。
- 完整旧测试集：未能启动；`pyexiv2` 依赖硬编码到不存在的 Homebrew Brotli 路径。

## 发布阻断项

### 1. 新用户无法完成试用、激活或购买闭环

严重度：P0

- 正式冻结包在没有授权时会阻止“开始分析”。
- 授权界面默认进入设计预览，所有试用、激活、支付、设备管理操作被禁用；只有显式设置 `EVENT_CULL_ENABLE_PAYMENT=1` 才会启用。
- 当前线上 OpenAPI 不包含 `/v1/trials/device`，因此即使手动启用按钮，“无需邮箱领取 1 天试用”也会返回 404。
- 当前线上健康检查显示：支付宝下单未就绪、微信回调未就绪、微信下单未就绪。

用户影响：第一次安装的用户既没有授权，又无法领取试用或购买，因此无法开始分析。

证据：`event_cull/license_ui.py:19-26, 121-150, 365-368`；`event_cull/app.py:2660-2669`；线上 `/api/health` 与 `/api/openapi.json`。

### 2. 授权失败时错误提示回调会再次报错

严重度：P0/P1

两个后台错误处理都把 `except ... as error` 中的异常变量延迟给 lambda 使用。Python 会在 `except` 结束后清除异常变量，因此 Tk 下一轮执行 lambda 时会出现 `NameError`。授权失败后，用户可能看不到原因，且界面控制保持禁用。

证据：`event_cull/license_ui.py:62-69, 320-332`；Ruff 明确报告两处 `F821 Undefined name error`。

### 3. 自动更新在线接口不存在

严重度：P1

客户端请求 `https://cull.lhxx.online/api/v1/app-updates/macos`，线上返回 404；线上 OpenAPI 也没有该路由。客户端把网络错误与“没有新版本”都静默转换为 `None`，所以用户不会收到错误，也永远不会看到新版本提示。

证据：`event_cull/updater.py:22-25, 61-75`；在线 GET 返回 `404 {"detail":"Not Found"}`。

### 4. 安装包版本元数据错误

严重度：P1

界面显示 `v2.0.5`，但 `.app/Contents/Info.plist` 的 `CFBundleShortVersionString` 是 `0.0.0`。Finder、系统日志、安装器和后续更新逻辑看到的版本与应用内部不一致。

同时，当前 `CFBundleIdentifier` 是中文可执行名而不是稳定的反向域名标识，打包配置没有正式签名身份。

证据：`event_cull/build_info.py:3`；`照片原图快速筛选器.spec:65, 77-87`；构建产物 Info.plist 与 `codesign -dv`。

## 已确认的产品 Bug

### 5. 顶部流程第 4 步被裁掉

严重度：P1

代码创建了 4 步（导入照片、AI 分析、人工复核、写入评级），但当前窗口截图只显示前 3 步；“写入评级”完全不可见。流程带的 `pack + expand` 布局在当前窗口宽度下溢出。

证据：当前 v2.0.5 主界面截图；`event_cull/app.py:1051-1066`。

### 6. 追加照片后任务名中的张数不会更新

严重度：P1

任务第一次导入后已有 `current_task_id`，后续追加照片时 `_ensure_task_identity` 立即返回，任务标题和历史记录名称继续保留第一次导入时的张数。

复现：先导入 1 张，再追加 1 张，标题仍为 `... · 1 张`。

证据：`event_cull/app.py:2318-2326, 2349-2361`；本次直接调用复现成功。

### 7. 导入统计在 PNG/TIFF/HEIC 等格式下自相矛盾

严重度：P2

统计内部有 `other` 数量，但文案只显示 JPG、RAW 与合计。例如 JPG 2、RAW 1、PNG 1 会显示“JPG 2 张 · RAW 1 张 · 合计 4 张照片”，用户会误以为少算或重复算了 1 张。

证据：`event_cull/app.py:126-128, 2038-2052, 2329-2340`。

### 8. macOS 辅助功能树几乎没有应用内容

严重度：P1（可访问性）

在主窗口、授权窗口和历史窗口的辅助功能快照中，只能读取窗口标题、系统窗口按钮与菜单栏；工作区按钮、输入框、表格和照片区域没有暴露。VoiceOver 用户无法可靠理解或操作核心流程，UI 自动化也只能依赖坐标。

证据：本次 macOS AX 快照。

### 9. 空状态仍显示无意义滚动条

严重度：P3

中央照片区为 0 张时仍显示完整垂直滚动条，形成可滚动的错觉，也增加视觉噪音。

证据：当前 v2.0.5 主界面截图。

## 工程与发布风险

### 10. 安装包体积约 1.0 GB

严重度：P2

其中 PyTorch 约 407 MB、OpenCV 约 134 MB、ONNX Runtime 约 70 MB。对首次下载、更新、分发带宽和启动扫描都很不利。当前更新方案还要求重新下载完整包。

### 11. 完整测试套件无法运行

严重度：P2

`tests/conftest.py` 导入 `pyexiv2` 时，动态库仍引用 `/opt/homebrew/opt/brotli/lib/libbrotlidec.1.dylib`，当前机器不存在该文件，因此整个旧测试套件在收集阶段退出。当前能运行的只是 94 项 `mvp_tests`。

### 12. 静态检查未通过

严重度：P2

Ruff 共报告 33 项，其中绝大多数是质量问题；最重要的是授权错误回调两处 `F821`，属于真实运行时故障。另有重复字典键、未使用导入和若干潜在维护风险。

## 建议修复顺序

1. 打通正式授权开关、部署设备试用路由、配置微信/支付宝，并修复授权错误回调。
2. 部署更新清单接口，修正 Info.plist 版本、Bundle ID 与正式签名/公证流程。
3. 修复第 4 步布局与追加导入后的任务名更新。
4. 补齐“其他格式”统计、辅助功能语义与空状态滚动条。
5. 精简安装包，并恢复完整测试套件与 Ruff 门禁。

## 审查限制

- 没有发起真实支付、没有领取真实设备试用，也没有写入任何用户照片或 XMP。
- 因当前 Tk 控件未暴露到 macOS 辅助功能树，部分页面无法进行稳定的逐控件自动化；结论由当前界面截图、代码路径、在线只读接口和测试结果交叉验证。
- 本报告只诊断，没有修改应用源代码。
