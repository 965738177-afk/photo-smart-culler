# 婚礼照片内容选片规则 v1

制定日期：2026-09-28。定位：产品规则与后续实现的验收标准。

历史版本：本文件的 45 条规则已扩展为 [v2 的 240 条规则库](wedding-content-selection-policy-v2-240.md)。后续以 v2 编号管理，本文件保留作版本参考，不与 v2 叠加计算。

本文件规定“软件应当怎样选”，不表示所有内容识别已经实现。当前实际能力与已完成的修正见 [婚礼选片规则与迭代记录](wedding-selection-rules.md)。

## 一、选择顺序与星级含义

先判断照片类型，再检查主体可用性和该类型的表情/动作要求，最后在同场景中比较情绪、构图与重复。清晰背景、笑脸数量、目标张数都不能抵消主体明显失误。

| 星级 | 定义 | 适用情况 |
| --- | --- | --- |
| 3 星 | 精选推荐 | 主体可用，满足该类型的表情和动作要求，在同组中有明确优势，适合优先交付 |
| 2 星 | 优质备用 | 本身可交付，但不如首选；或提供有价值的另一种景别、动作、情绪 |
| 1 星 | 初选复核 | 关键瞬间值得保留，但有需人工确认的疑点；或照片类型/主体状态判断不充分 |
| 无星 | 本次未入选 | 明显失误、普通过渡帧、低价值重复，或同组中已存在明显更好的替代 |

无星不等于删除。1 星及以上均属于软件当前“已选”范围，导出时用户可以按星级选择。因此 1 星只留有价值的疑问帧，不把所有不确定照片都塞进已选。

G01：3 星没有强制数量或比例；一组没有合格照片时可以没有 3 星。

G02：关键瞬间不能因为没笑、没看镜头而漏选；普通摆拍不能因为是婚礼照片就容忍明显的表情失误。

G03：手动星级优先。选片偏好只能在内容和质量门槛通过后排序，不能把明确失误提升为自动 3 星。

G04：模型输出必须区分“有充分证据”和“无法确定”。未检测到人脸、眼睛、手，不等于确定侧脸、闭眼、手部缺失。

## 二、照片类型及主要判断标准

| 类型 | 3 星应优先的内容 | 需要降级或不选的内容 |
| --- | --- | --- |
| 正式合影 | 必须入镜的人齐全、关键人物状态好、全员视线协调、笑容自然、队形完整 | 意外闭眼、关键人物扭头、脸被挡、队形缺失 |
| 新人/单人摆拍 | 角度好、姿态完成、表情自然、衣服和身体线条舒展，侧脸背影也可 | 普通调整动作、姿态别扭、表情切换中断 |
| 仪式与情绪 | 动作关键点、真实反应、人物关系和事件表达清楚 | 关键动作无法辨认、严重虚焦；有价值但不确定的瞬间复核 |
| 敬酒与互动 | 互动成立、接触或碰杯瞬间清楚、人物表情自然 | 普通准备帧、无意义遮挡、失去交流关系 |
| 动作抓拍/网感 | 动作有明确意图、姿态连贯舒展、画面有节奏，主体与氛围协调 | 无意图过渡动作、意外失衡、无表现价值的重复 |
| 细节/环境 | 关键细节清楚、主体完整、构图整洁、有故事和场地交代价值 | 关键细节被遮、主体不清、相同视角低价值重复 |

类型有歧义时保留有价值的代表图供复核。不能把“多人”“并排”“距离近”等单一信号直接当成摆拍、拥抱或敬酒的确定分类。

## 三、正式合影：最优先改进的规则

适用于明确面向摄影师的新人父母合影、宾客合影、伴郎伴娘合影、门口留念等。

P01：先确认同组人物是否一致。人数变了、有人加入退出时，分别选择代表图；不能因为后一张人更多，就把前一组全部淘汰。

P02：关键人物可用是精选前提。新人、被确认的父母或其他指定人物出现明显虚焦、意外闭眼、脸被挡、尴尬过渡表情时，不自动给 3 星。

P03：全员状态优先于个别人的表现。不能用“3 人大笑的加分”抵消“另 1 人明显闭眼或扭头”的失误。

P04：正常正式合影优先大家面向拍摄方向、眼睛状态自然、表情协调的照片。婴幼儿、用户标注的特殊情况采用单独容错，不要求所有人机械地看同一像素位置。

P05：同组全员状态都通过后，大家自然大笑的版本优先于普通微笑；自然微笑优先于僵硬笑容。长辈的温和表情可视为合格，不强制露齿或夸张大笑。

P06：正常笑到眯眼可以精选；眨眼导致面部表情中断不精选。判断证据包括双眼对称、嘴角/面颊表情、头部姿态及相邻帧。判断不清时进入复核，不武断当废片。

P07：一只眼意外闭合、有明显扭头/遮挡、低头查看物品、正开口说话而表情不自然等，不作为正式合影首选。明确设计的眨眼玩笑照按互动照片另评。

P08：其次检查队形、肩膀与脸的遮挡、边缘人物被切、头顶杂物与穿帮。全身照中明显误切脚或关键肢体影响交付时降级；半身构图不要求脚入镜。

P09：同一阵容、同一机位、同一姿势的一组，默认留 1 张 3 星。仅当备用有实际用途时加 1 张 2 星；其余普通重复不标星。若全员表情都存在明显问题，关键合影留最可用的一张 1 星供人工确认。

组内比较顺序：关键人物可用 → 全员状态协调 → 自然大笑/微笑 → 主体清晰 → 队形与构图 → 技术细微差异。

## 四、新人写真、单人肖像与氛围照

R01：不要求看镜头、不要求笑。侧脸、低头、对视、背影、牵手走远等，只要姿态成立且符合拍摄意图，都可给 3 星。

R02：优先颈肩线条自然、体态舒展、面部角度好、服装状态整洁、人与环境关系明确的画面。不能把“正脸数量”当作写真美感。

R03：动作半成品通常不选：刚抬手未形成姿态、调整衣服、准备转身、失去平衡的跨步、表情切换中断。但同样姿势如果表达了明确情绪或有意设计，允许保留。

R04：闭眼氛围照需面部放松、姿态完整、画面意图清楚；不能把偶然眨眼自动解释为氛围感。

R05：同组保留有实质差异的版本，例如正面近景、侧面全身、牵手背影。只有头微动或角度微变的连续帧，选姿态和表情最好的一张。

## 五、仪式与真实情绪

E01：先保留关键环节的可用代表：入场、父亲交接、誓言、交换戒指、掀头纱、接吻、拥抱、父母反应、退场。环节覆盖不等于每张都给 3 星。

E02：亲吻、拥抱、祈愿、流泪、阅读誓言、听讲话等，闭眼、低头和不笑可能是合理状态，按事件表达判断。

E03：关键动作应看得明白。例如交换戒指能看清手与戒指关系，父亲交接能看清人与手的连接，接吻优先接触成立、姿态自然的帧。

E04：同一事件优先保留“事件全貌”和“有独立价值的反应/细节”。例如交接全景与父亲表情特写可以分别精选，不按普通重复照片合并。

E05：真实哭泣、笑哭、惊喜不按“尴尬表情”统一淘汰。比较的是情绪是否真切、画面是否可用，不是面部是否符合摆拍笑容。

E06：只有一张的关键瞬间，存在轻微技术或表情疑点时可给 1 星，提醒人工处理。严重模糊无法辨认事件的照片不自动给 3 星，仍可在关键瞬间复核列表保留记录。

## 六、敬酒、接亲游戏和多人互动

I01：优先动作真正发生、人物之间有交流、情绪自然的帧。例如碰杯、互相笑、递茶、递红包、拥抱和击掌。

I02：人物看彼此、看杯子、看长辈是正常互动。不能用正式合影的“全员看镜头”门槛评价。

I03：碰杯优先杯子接近/接触清楚、手部姿态自然；杯子挡住关键人物整张脸、刚起手的普通准备帧优先降级。明显遮挡有情绪或故事价值时留复核。

I04：讲话张嘴、举杯喝酒、游戏吐舌头等按情境评价。传统留念中意外吐舌头不作首选；明确的搞怪互动如果动作、笑容和参与者状态协调，可以精选。

I05：一桌敬酒以一张完整互动为主，另有独立的反应特写才增加保留；不同桌或不同宾客不能当同一组重复删选。

## 七、动作完成、手部、遮挡与“网感”

A01：优先具有明确视觉意图的动作阶段：转身姿态舒展、步态自然、跳跃/抛花达到有表现力的瞬间、裙摆头纱展开。关键阶段不是固定的动作最高点，要结合表情和构图。

A02：动作进行中不等于半成品。动态摄影允许手臂伸展、离地、倾身；普通过渡帧的问题是姿态无意图、重心别扭、表情中断且没有事件价值。

A03：手部检查重点是交付价值：婚戒、交换戒指、牵手、敬茶等必须看清关键关系；普通半身肖像允许手在画外。故意裁切和意外切断要分别判断。

A04：遮挡按主体与意图判断。头纱、花束、前景可形成氛围；但关键人物面部/关键动作被无意义遮住且有更好替代时不选。软件不确定意图时留有价值代表复核。

A05：构图比较包含主体突出、视觉平衡、视线/动作方向留有合理空间、背景整洁、服装与肢体线条、场景层次。不强制居中或三分法；留白可以是设计。

A06：“网感”采用用户样片偏好排序，比较自然度、姿态、光影、色彩、节奏和画面情绪。它不覆盖正式合影全员状态，也不把所有清晰高对比照片判为好片。

A07：运动模糊可在主体与动作关系明确、效果有意且符合样片风格时保留；明显对焦失败不能因为动态题材而直接获得精选。

## 八、静物、场地与细节

D01：婚戒、婚鞋、手捧花、请柬、婚纱细节、桌花、宴会厅和仪式场地分别检查主体完整、关键纹理和文字、光线与背景。跳过笑脸和视线要求。

D02：同一细节优先一张全貌与一张有价值的局部；同机位只改少量距离的重复不全部保留。

D03：场地照片强调空间交代、层次和布置完整，允许人物极小。镜面/金属高光、舞台灯光和暗背景不能单独构成曝光废片，需检查关键主体细节是否可用。

## 九、同场景与同一批人的比较

C01：建立“事件、参与者组合、景别/机位、动作主题”四层比较范围。时间与视觉相似度用于提出候选，不能单独证明同一个场景。

C02：正式合影换阵容即新组；同一阵容换机位/景别可作为不同用途；微小动作变化仍归同组择优。

C03：多人互动或仪式前后帧可以同属一个事件，但要保留独立的关键阶段。不能把举杯、碰杯与人物反应全部折叠为一张。

C04：跨组自动合并需要充分证据：参与者一致、环境吻合、时间合理、事件无冲突。模糊脸、遮挡或身份匹配不确定时保持独立，并可提示人工合并。

C05：关系身份由用户确认：新人、双方父母、指定重要宾客。外貌、年龄、站位和衣服只能提出候选，不能自动断言谁是父母。

C06：没有确认身份时只评价“主要人物/其他参与者”。关键人物确认后，同组照片使用一致的角色优先级，不能因为某张没检测到新人就提高其他人的平均分。

## 十、实现所需的证据与解释

每张照片至少应记录：内容类型及确定程度、所属事件/比较组、已确认的角色、逐脸可见性与清晰度、双眼状态、视线/头部方向、笑容与表情、关键动作可见性、质量疑点、推荐原因。

逐脸检测需区分：睁眼、疑似闭眼、疑似笑眯眼、无法确定。没有相邻帧和足够面部证据时，不能把单张小眼睛照片断言为“瞬间眨眼”。

解释示例：

- “同组合影：关键人物状态正常，全员视线协调、笑容自然，推荐 3 星。”
- “同组合影有更完整的版本；当前一人疑似意外闭眼，留作 1 星复核。”
- “仪式拥抱：闭眼符合情境，人物关系清楚，推荐保留。”
- “转身动作尚未形成姿态，且同组有完成版本，当前不选。”
- “人物遮挡导致眼部状态无法判断，关键瞬间留作复核。”

不要在检测证据不足时显示“全员正视镜头”“一定是父母”“确认废片”等确定结论。

## 十一、验收样例

以下是规则期望，不是当前模型准确率声明。

| 对照照片 | 期望结果 |
| --- | --- |
| 同阵容全员自然大笑 vs 一人意外闭眼其余大笑 | 前者优先 3 星；后者不自动 3 星 |
| 全员自然微笑 vs 两人大笑但关键人物扭头 | 前者优先；不让局部笑容抵消关键人物失误 |
| 自然笑眯眼 vs 表情中断的眨眼 | 有充分证据时优先前者；不确定时人工复核 |
| 父亲含泪拥抱 vs 普通僵硬合影 | 各按类型判断，不能因父亲不笑淘汰情绪镜头 |
| 五人合影 vs 六人合影新增一位宾客 | 两个阵容分别择优，不能只选六人那张 |
| 转身完成的侧脸 vs 刚抬手调整衣服的正脸 | 前者可精选，后者普通过渡帧不选 |
| 背影牵手走远 vs 面向镜头但虚焦 | 背影可精选，不能靠正脸加分掩盖虚焦 |
| 戒指特写清楚、手部关系完整 vs 戒指被手挡 | 前者优先；关键细节不可见的版本降级 |
| 搞怪游戏有意吐舌头 vs 正式合影意外吐舌头 | 游戏按互动评，正式合影不作首选 |
| 同事件全景与父母反应特写 | 各有故事用途时都可保留，不作普通重复 |

验收使用真实连拍原图，由摄影师标出首选、备用、不选和理由；调规则的样本与最终验证样本分开。分别统计首选命中、3 星明显失误、关键环节漏选、保留的重复与处理耗时，确认变化后再发布。

## 十二、后续实现优先级

1. 正式合影逐人检查与精选门槛，解决当前最直接的误选。
2. 内容分类与仪式/互动豁免，减少真实情绪误杀。
3. 同阵容分组及跨组比较，减少重复和错误合并。
4. 角色确认、动作与构图证据、用户样片偏好，逐步补充婚礼风格评价。

规则版本和模型版本分别记录。任何新增内容能力通过真实样片验收前，不对外宣称已准确识别。
