# 秒选首次运行与故障排查

适用版本：`v2.1.6` Apple Silicon 团队授权测试版（`秒选-2.1.6-macOS-Apple-Silicon-团队授权测试版.zip`）。

> 这是一份团队测试包：使用的是 `ad-hoc` 代码签名，尚未使用 Apple Developer ID 签名或 Apple 公证。因此，在另一台 Mac 上首次打开时，**有可能**被 Gatekeeper 拦截。这是 macOS 的安全机制，不代表 App 或照片出了问题。

## 先确认这三件事

1. **芯片与系统**：此包仅支持 Apple Silicon（M1、M2、M3、M4 等）Mac，且需要 macOS 11 或更高版本；Intel Mac 不能运行这个包。
2. **来源与完整性**：只从项目发布页或发送者提供的原始压缩包获取，等待压缩包完整下载、完整解压后再打开。不要从压缩包预览界面直接运行，也不要修改 `.app` 包内的文件。
3. **安装位置**：建议把解压出的 App 拖到“应用程序”文件夹后再打开；不要长期从下载目录、网盘同步目录或移动硬盘中直接运行。

团队授权测试版需要由团队主人先在管理网站邀请成员；成员在 App 左下角点“团队授权”，以受邀请的团队邮箱收取验证码并完成本机授权。照片和缩略图不会发送到授权服务。

## 首次打开：不需要开启“任何来源”

**不建议**开启“允许任何来源”，也不要执行 `spctl --master-disable`、关闭 SIP 或关闭整台 Mac 的安全防护。

出现“无法验证开发者”“Apple 无法检查是否包含恶意软件”或“无法打开，因为开发者无法验证”时，按以下任一方式操作：

### 方法 A：Finder 右键打开（优先）

1. 在 Finder 中选中 `照片智能筛选器 16.app`。
2. 按住 `Control` 点按 App，或点按右键，选择“打开”。
3. 在第二个确认框中再次点“打开”。

这只会允许这一个 App，之后可正常双击启动。

### 方法 B：系统设置中“仍要打开”

1. 先双击 App 一次，让 macOS 显示拦截提示。
2. 打开“系统设置 → 隐私与安全性”，向下滚动到“安全性”。
3. 找到“已阻止使用……”，点“仍要打开”，再输入本机登录密码确认。

“仍要打开”通常只在首次拦截后的约一小时内出现；如果没有看到，重新双击一次 App 后再回到该页。Apple 的当前官方步骤见：[在 Mac 上安全地打开 App](https://support.apple.com/zh-cn/102445)。

## 常见提示与处理方法

| 现象或提示 | 常见原因 | 安全处理方法 |
| --- | --- | --- |
| “无法验证开发者” / “Apple 无法检查是否包含恶意软件” | 团队测试包未做 Apple 公证 | 使用上面的 Finder 右键打开或“隐私与安全性 → 仍要打开”；不要开启“任何来源”。 |
| “App 已损坏，无法打开” | 压缩包未下载完整、解压过程损坏、文件被改动，或下载隔离标记仍在 | 先删除该副本并重新下载、重新解压；确认来源和校验值无误后，才使用下方“隔离标记”办法。 |
| “无法打开此版本的应用程序” / App 一闪即退 | Intel Mac、macOS 过旧，或 App 从未解压完整 | 在“关于本机”确认是 Apple 芯片且系统为 macOS 11+；重新解压并从“应用程序”中启动。Intel Mac 请索取 Intel 版。 |
| “此 App 已被管理员阻止” / 没有“仍要打开”按钮 | 公司或学校的 MDM 安全策略禁止未公证 App | 不要尝试绕过组织策略；请联系设备管理员，由管理员评估或提供受信任的正式公证版。 |
| 双击没有反应，或每次都弹安全提示 | App 仍在压缩包、下载目录或云盘同步目录；首次授权未完成 | 把 App 拖到“应用程序”，按右键打开一次；确认后以后直接双击。 |
| Finder 显示的版本不对 | 保留了旧副本，或打开的是旧 App | Finder 选中 App，按 `Command-I` 查看版本应为 `2.1.6`；删除旧测试副本后再拖入新版。 |
| 提示没有权限访问“桌面”“文稿”或外接硬盘 | macOS 的“文件与文件夹”或可移动宗卷权限未授予 | 在导入对话框中重新选择照片文件夹并点“允许”；仍不行时到“系统设置 → 隐私与安全性 → 文件与文件夹”允许本 App 访问相应位置。 |
| 文件夹能选，但照片导不进来 | 文件格式不受支持、文件正在同步、网络磁盘断开或读权限不足 | 确认原片已完整同步到本地；先复制少量 JPG/RAW 到本机磁盘测试；检查该文件夹不是只读。 |
| RAW 没有缩略图或预览很慢 | 该相机 RAW 没有可读嵌入预览、机型较新，或源文件在慢速外接盘/网盘 | 优先导入同名 JPG+RAW；将一小批原片复制到本机 SSD 测试；仍失败请保留一张原始 RAW 供排查。原图不会被修改。 |
| 大批照片滚动、缩略图或分析看起来较慢 | 首次解码、外接盘速度、内存压力，或其他照片软件同时读取同一批原片 | 等待当前批次的缩略图完成；关闭不需要的 Lightroom、同步盘和大型程序；降低缩略图比例或拆分为较小批次后重试。 |
| 点击图片没有星级 / 显示“等待 AI 分析” | 分析尚未完成，或正在滚动加载更多照片 | 等待分析进度结束后再复核；也可在右侧手动设置 0、1、2、3★。1★是“初选复核”，2★是“优质备用”，3★是“精选推荐”。 |
| 选图数量比目标高 | 目标数量是保底范围而不是强制截断；不同场景、独立主体和关键瞬间会优先保留 | 在“AI 挑图设置”调整目标下限/上限和每组优选张数。结果可以高于建议数，但不会低于设置下限，除非原始照片本身不足。 |
| 不能写入 XMP / 写入按钮不可用 | Lightroom 正在运行、原片目录只读、磁盘空间不足，或选择了跳过已有星级 | 完全退出 Lightroom Classic；确认照片目录可写且有可用空间；检查“写入方式”。App 只写同名 `.xmp`，不修改 RAW/JPG 像素。 |
| Lightroom 里没有看到新星级 | Lightroom 尚未重新读取旁车，或已有星级被“跳过已有星级”保护 | 关闭/重新打开 Lightroom，在图库中选中照片并执行“元数据 → 从文件读取元数据”；必要时核对写入方式。 |
| 选片偏好校准提示样本不足、文件不匹配或版本不兼容 | 校准照片少于要求、导出时重命名、缺少星级元数据，或沿用了旧版本校准文件 | 使用至少 80 张原片与至少 12 张最高星级样本；导出的 JPG 要保留全部元数据且不改名；重新导入一次校准资料。 |
| 团队授权验证码收不到 / 提示未受邀请 | 邮箱未在团队名单中、验证码过期，或 SMTP 未配置 | 让团队主人在 `https://cull.lhxx.online/team/` 确认邀请邮箱；返回 App 重新发送验证码。若所有人都收不到，请让部署管理员检查邮件服务。 |
| 团队授权提示设备数量已满 | 该成员已达到团队主人设置的设备上限 | 让团队主人在管理网站移除旧 Mac，或由成员在左下角“团队授权设备”移除自己不再使用的设备，再在新 Mac 验证邮箱。 |
| 团队成员离职后仍能离线使用 | App 已获得短期离线租约 | 团队主人在网站撤销成员后，后续联网会立即失效；离线设备最长在 24 小时宽限结束后失效。 |
| 授权/试用网络提示（正式版） | 首次验证、刷新授权或网络连接失败 | 检查网络、日期与时间设置后重试；不要把团队验证码、管理网站会话或个人账号发给他人。 |

## 仅在确认来源可信后：处理隔离标记

如果重新下载、重新解压后仍出现“已损坏”，且你已经确认压缩包来自可信发送者、校验值与发布值一致，可以仅对这一份 App 删除下载隔离标记。

1. 将 App 放入“应用程序”文件夹。
2. 打开“终端”，输入下面命令，**把 App 从 Finder 拖进终端窗口**以自动补全正确路径，再按回车：

```bash
xattr -dr com.apple.quarantine
```

3. 再按 Finder 右键“打开”。

这个命令只会移除 macOS 的下载隔离标记，**不会修复损坏文件，也不会验证文件是否安全**。不能确认来源或校验值时，请不要使用它；直接删除并重新索取安装包。

可选校验：在终端运行下面命令（把压缩包拖入命令末尾），并与团队主人在本次发布通知中提供的 v2.1.6 SHA-256 值核对：

```text
请以本次发布通知提供的值为准
```

```bash
shasum -a 256
```

## 发生闪退时，请这样反馈

请不要反复强制打开或修改原片。先记录以下信息，能显著缩短定位时间：

1. App 版本、macOS 版本和芯片类型（“ → 关于本机”）。
2. 发生在“启动、导入、分析、滚动、选星、写入 XMP”中的哪一步，以及是否每次都能复现。
3. 原片类型、总张数、是否位于外接盘/网盘；不要发送客户原片。
4. 完整错误提示截图；如有闪退报告，在“控制台”App 的“崩溃报告”中导出对应条目。
5. 若能安全复现，可另附一张已脱敏的测试照片和操作步骤。

## 发布方待办：避免用户首次手动放行

要让公开发行版在大多数 Mac 上无需“仍要打开”，发布方必须使用 Apple Developer ID Application 证书对最终 `.app` 签名，并提交 Apple 公证（notarization），随后再封装和分发。**仅做 ad-hoc 签名的测试包无法达到这个体验。**
