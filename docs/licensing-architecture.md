# 秒选授权与支付架构

## 三个环境

| 环境 | 用途 | 是否需要登录 | 是否接真实支付 |
| --- | --- | --- | --- |
| development | 开发者在本机调试 | 否；仅允许明确开启的本地模拟授权 | 否 |
| staging | 内测、验收和支付联调 | 是；使用测试账号 | 微信/支付宝沙箱或测试订单 |
| production | 给用户发布的签名安装包 | 是；首次激活后凭证存入系统钥匙串 | 是 |

开发模式不得写入正式安装包；正式版也不得接受环境变量、隐藏菜单或本地文件作为授权。

## 支付到激活

1. 官网向授权服务创建待支付订单，订单包含套餐和购买邮箱。
2. 用户通过微信支付或支付宝完成付款。
3. 仅在授权服务验证支付平台的签名回调后，订单才变为已支付并开通套餐。
4. 用户在秒选输入邮箱并完成一次性验证码验证。
5. 软件提交随机生成、保存在系统钥匙串中的安装 ID；服务端以事务确保账户最多 3 台设备，并返回带签名的授权租约。
6. 软件使用内置公钥校验授权租约；每 24 小时尝试刷新。服务器下发的离线截止时间最长为 5 天，客户端不可自行延长。

## 服务端最小接口

- `POST /v1/checkout/orders`：创建待支付订单。
- `POST /v1/payments/wechat/notify`、`POST /v1/payments/alipay/notify`：验签并开通权益。
- `POST /v1/auth/email-codes`、`POST /v1/auth/sessions`：邮箱验证码登录。
- `POST /v1/licenses/activate`：绑定设备，返回签名授权。
- `POST /v1/licenses/refresh`：刷新授权租约。
- `DELETE /v1/devices/{id}`：官网“我的设备”解绑旧设备。

支付密钥、回调验签私钥和授权签名私钥只能保存在服务器的密钥管理/环境配置中，绝不打包进客户端。
