# 秒选：内置内容分析（v2.1.24）

更新：2026-09-29。完整安装包自带推理组件、视觉模型和 240 条规则库；用户不需要安装 Ollama、执行命令或另行下载模型。桌面婚礼场景默认开启“内置婚礼内容细查”，其他题材仍走原有题材规则。

## 用户怎么用

1. 安装完整版本，导入照片。
2. 在挑图设置中选择“婚礼”，用途可选自动、正式合影、纪实互动等。
3. 确认规则并开始分析。软件复用现有预览，在后台启动随包提供的本地模型；完成、取消或失败时释放该进程。

设置中的“检查内置组件”只检查安装文件，不在界面线程加载模型，也不连接 Ollama。关闭内容细查可以使用原有较快的基础检测；这不会变成同等能力的内容分析。模型不上传照片，不进行运行时下载；付费、授权和版本更新仍有原来的独立联网流程。

## 包里实际有什么

| 组件 | 当前用途与边界 |
| --- | --- |
| OpenCV 与 FER+ | 基础技术、人脸、眼睛和笑容证据；不是逐人精确视线识别 |
| MobileNet ONNX | 用户偏好校准特征，不是婚礼内容识别 |
| llama.cpp b11242 | 随包启动的离线推理组件；Mac Apple Silicon 使用 Metal，Windows x64 使用便携 CPU 版本 |
| Qwen3-VL-4B-Instruct Q4_K_M + F16 视觉投影 | 单张场景、表情用途、主体与动作疑点的结构化观察 |
| 240 条婚礼规则库 | 程序约束、按章节提供给内容模型的参考及人工复核依据；不等于 240 项识别能力全部实现 |

所用权重来自 [Qwen 官方 GGUF 仓库](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct-GGUF)，运行组件来自 [llama.cpp 官方 b11242 发布](https://github.com/ggml-org/llama.cpp/releases/tag/b11242)。Qwen Apache-2.0 与 llama.cpp MIT 许可证随安装包提供，权重不作修改。

两份权重共 3,333,461,920 字节（约 3.33 GB / 3.10 GiB），不包含应用与推理组件。下载/磁盘体量不是总运行内存；大量照片需要明显更多分析时间。模型与运行器版本和权重 SHA-256 固定，构建前校验，分析前在后台复验，进程内复用已验证的未变更文件。

## 观察与星级不是一回事

复用已有照片预览 → 基础技术检测 → 内容分类 → 对应章节加基础、分组和叙事规则 → 校验观察字段 → 程序证据门槛与同组比较 → 建议星级。

每张内容观察包含五项 pass/fail/unknown：主体可用、表情合用途、动作完成、合影完整、视线协调，以及观察文字和有依据的规则编号。模型不直接决定星级、不猜人物身份；照片里的文字不作为指令。

- 自动仅输出 0/1/3 星，2 星保留给摄影师人工确认。
- 内容观察未知、失败或技术证据有冲突时不能强推 3 星；失败不作为成功特征缓存。
- 1 星是建议保留的原片；3 星是保留池里的精修候选，仍须摄影师验收，不是完美保证。
- 模型观察可能出错；增加规则、结构化输出或模型打包不能代替真实样片质量验证。

## 安全与取消

每个分析任务只创建一个模型客户端，同一时刻一次推理。程序启动自己的进程，只监听随机的 127.0.0.1 端口，使用临时密钥，忽略系统代理，拒绝重定向。启动参数明确离线、禁用 Web 界面；不复用或终止用户自己的 Ollama/其他模型进程。

模型加载等待上限 90 秒，单次内容请求上限 180 秒；等待期间检查暂停/取消。取消终止本任务的模型进程，超时作为失败而不是假报用户取消。连续两次观察失败后停止本批重试，后续仅基础保留、不自动推荐精修候选。

## 当前不能保证的事情

精确判断全员视线与眨眼、自动确认新人和父母、跨组跟踪同一批人、相邻帧完整动作比较、整场故事完整性及“网感”都未完成可靠验收。单张模型不会假装具备这些序列和身份能力；相关规则仍是参考/待验证。

当前已验证安装资源、连续结构化推理、未知值和进程退出；这不是婚礼选片准确率。应使用摄影师标注的独立合影、仪式、互动、弱光样本，核对误选、漏选、组内首选和耗时，再逐步调整。不能宣称“规则全实现”或“无 bug”。

构建者运行 scripts/prepare_bundled_content.py --platform darwin-arm64 或 --platform win32-amd64 取得校验过的离线资源，再使用对应打包配置；这不是用户安装步骤。Windows 构建配置已同步，原生运行需在 Windows 上验收。
